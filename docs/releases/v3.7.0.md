## 🎉 V3.7 — Ansible side: clone VMs from Packer templates

This release introduces the **Ansible side** of the VM Lifecycle Toolkit, giving the project a second concrete tool on top of the Packer templates: Ansible can now clone a Packer-built VM template on Proxmox, apply hardware overrides, start the clone, and (optionally) wait for SSH.

### 🆕 New

- New top-level `ansible/` directory with full scaffolding (`ansible.cfg`, `requirements.yml`, `requirements.txt`, static inventory, playbooks, roles)
- `proxmox_clone` role: clone from template + optional hardware overrides + start + optional SSH wait
- Static YAML inventory format for describing VMs to clone (`ansible/inventories/proxmox/hosts.yml`)
- Entry-point playbook: `ansible/playbooks/clone-from-template.yml`
- Dedicated `ansible@pam` user on Proxmox (parallel to `packer@pam`) with its own API token — setup in `BUILD.md` Step 1c

### 🔧 Technical choices

- Migrated to the **`community.proxmox`** collection (new in 2024, replaces the deprecated `community.general.proxmox_kvm` which will be removed in `community.general` 15.0.0)
- Python deps via **virtual environment** (recommended) due to Debian 13 / Ubuntu 24.04 PEP 668 enforcement + `proxmoxer >= 2.3` requirement (the apt-shipped `python3-proxmoxer` is too old)
- Self-signed Proxmox cert tolerance via `proxmox_api_validate_certs: false` (toggle for production use with a real CA-signed cert)
- Clone API semantics: `clone` is a trigger flag, `vmid` = source template VMID, `newid` = destination VMID (counter-intuitive but documented in the role)

### 📖 Docs

- New `ansible/README.md` with install steps, quick-start, secrets handling (env var or `ansible-vault`), roadmap
- `BUILD.md` extended with **Step 1c — Ansible user on Proxmox** (pveum commands + install deps)
- Main `README.md` layout tree updated to show the real `ansible/` content, V3.7 changelog entry, version badge bumped to v3.7
- `.gitignore` extended with `ansible/venv/`, `ansible/collections/`, `ansible/ansible.log`

### ⚠️ Known limitations

- **Proxmox only** in V3.7 — ESXi support planned for V3.7.2 (via `community.vmware` OVF deploy)
- **No post-clone configuration** — V3.7 only clones + starts. Post-install configuration roles (base_config, docker_host, webserver, etc.) planned for V3.7.1+
- **Static inventory only** — Dynamic inventory planned for V3.7.3

### 🔮 Roadmap

- **V3.7.1** — Post-clone configuration roles (base_config, docker_host, webserver, ...)
- **V3.7.2** — ESXi support (OVF deploy via `community.vmware` modules)
- **V3.7.3** — Dynamic inventory (query Proxmox API for existing VMs)
- **V3.7.4** — Decommission playbook (clean VM teardown)
- **V3.8** — Terraform side (first iteration)
